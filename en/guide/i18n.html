Internationalization 国际化 Guide ​

The library ships built-in Chinese (zh-CN) and English (en-US) locale packs: switch all component messages with one setLocale call, extend to any language via registerLocale, and share the same runtime API on both frameworks (@xui-design/vue / @xui-design/react).

How It Works ​

  • Message Layers: built-in component messages (Modal button text, Table empty state, DatePicker panel titles and weekdays, aria and placeholder text for Pagination / Breadcrumb / Skeleton / Select) are all read from the global locale pack; explicitly passed message props always take precedence.
  • Reactive Switching: setLocale notifies all subscribed components to re-render — via the useLocaleData composable on Vue and useSyncExternalStore on React — so mounted components update immediately.
  • Extending Languages: registerLocale accepts a partial locale pack grouped by component, shallow-merged group by group onto the base pack, so you only translate the groups you care about; function fields (e.g. selectRow / titleFormat) adapt to different word orders.

Built-in Messages (zh-CN) ​

  • Modal: 确认 (OK) / 取消 (Cancel); Popconfirm: 确定 (Confirm) / 取消 (Cancel)
  • Table: 暂无数据 (No data), 全选 (Select all), 选择第 N 行 (Select row N)
  • DatePicker: 请选择日期 (placeholder), 选择日期 (panel title), 上个月 / 下个月 (prev / next month), YYYY 年 MM 月 (title format), 日 一 二 … 六 (weekdays)
  • Select: 请选择 (trigger placeholder), 搜索... (search box placeholder and aria)
  • Pagination: 分页 (nav) / 上一页 (prev) / 下一页 (next); Breadcrumb: 面包屑 (nav); Skeleton: 加载中 (loading)

Examples ​

Each demo can be switched between Vue and React tabs for live interaction, with source code available per framework.

Built-in Locale Switching (setLocale) ​

setLocale('zh-CN' / 'en-US') instantly switches the built-in messages of every component: Modal buttons, Table empty state and row selection hints, DatePicker panel titles and weekdays, etc.

Vue
<script setup lang="ts">
import { computed, ref } from 'vue';
import { getLocale, setLocale } from '@xui-design/vue';
import { Button, DatePicker, Modal, Table, Tag } from '@xui-design/vue';
import { isZh } from '../../../i18n';

const current = ref(getLocale());
const visible = ref(false);

const columns = computed(() => [
  { key: 'name', title: isZh() ? '名称' : 'Name' },
  { key: 'age', title: isZh() ? '年龄' : 'Age' },
]);

const apply = (locale: string) => {
  setLocale(locale);
  current.value = getLocale();
};
</script>

<template>
  <div class="demo-column">
    <div class="demo-row">
      <Button type="primary" @click="apply('zh-CN')">{{ isZh() ? '中文' : 'Chinese' }}</Button>
      <Button @click="apply('en-US')">English</Button>
      <Tag type="primary">{{ current }}</Tag>
    </div>
    <div class="demo-row">
      <Button type="link" @click="visible = true">{{
        isZh() ? '打开 Modal' : 'Open Modal'
      }}</Button>
    </div>
    <Modal v-model:visible="visible" :title="isZh() ? '国际化演示' : 'i18n Demo'">
      {{
        isZh()
          ? '底部按钮文案随全局语言切换；点击确认或取消关闭。'
          : 'Footer button text follows the global locale; click OK or Cancel to close.'
      }}
    </Modal>
    <Table :columns="columns" :data-source="[]" />
    <DatePicker style="width: 240px" />
  </div>
</template>

Registering Custom Locales (registerLocale) ​

registerLocale registers any language grouped by component (shallow merge per group; uncovered groups fall back to the base pack at registration time) and takes effect immediately after setLocale switches to it.

Vue
<script setup lang="ts">
import { computed, ref } from 'vue';
import { getLocale, registerLocale, setLocale } from '@xui-design/vue';
import { Button, Modal, Popconfirm, Table, Tag } from '@xui-design/vue';
import { isZh } from '../../../i18n';

const current = ref(getLocale());
const visible = ref(false);
const registered = ref(false);

const columns = computed(() => [
  { key: 'name', title: isZh() ? '名称' : 'Name' },
  { key: 'age', title: isZh() ? '年龄' : 'Age' },
]);

const registerJapanese = () => {
  registerLocale('ja-JP', {
    modal: { ok: 'OK', cancel: 'キャンセル' },
    popconfirm: { confirm: 'OK', cancel: 'キャンセル' },
    table: { empty: 'データがありません' },
  });
  registered.value = true;
  apply('ja-JP');
};

const apply = (locale: string) => {
  setLocale(locale);
  current.value = getLocale();
};
</script>

<template>
  <div class="demo-column">
    <div class="demo-row">
      <Button type="primary" :disabled="registered" @click="registerJapanese">
        {{
          registered
            ? isZh()
              ? '已注册 ja-JP'
              : 'ja-JP registered'
            : isZh()
              ? '注册日语语言包'
              : 'Register Japanese locale'
        }}
      </Button>
      <Button @click="apply('zh-CN')">{{ isZh() ? '回到中文' : 'Back to Chinese' }}</Button>
      <Tag type="primary">{{ current }}</Tag>
    </div>
    <div class="demo-row">
      <Button type="link" @click="visible = true">{{
        isZh() ? '打开 Modal' : 'Open Modal'
      }}</Button>
      <Popconfirm
        :content="isZh() ? '确认删除这条数据吗？' : 'Are you sure you want to delete this record?'"
      >
        <Button>{{ isZh() ? '删除' : 'Delete' }}</Button>
      </Popconfirm>
    </div>
    <Modal v-model:visible="visible" :title="isZh() ? '自定义语言包' : 'Custom Locale'">
      {{
        isZh()
          ? '注册后所有组件文案按新语言渲染，未覆盖的分组回退注册时的基底包。'
          : 'After registration, all component text renders in the new language; uncovered groups fall back to the base pack at registration time.'
      }}
    </Modal>
    <Table :columns="columns" :data-source="[]" />
  </div>
</template>

API ​

The i18n API is provided by @xui-design/shared (framework-agnostic implementation). @xui-design/vue and @xui-design/react re-export it under the same names with identical behavior.

Imperative Methods ​

Imperative Methods

MethodSignatureDescription
setLocale(locale: string) => voidSwitches the current locale; unregistered names are silently ignored, and unchanged values return silently
getLocale() => stringReads the current locale name (defaults to DEFAULT_LOCALE)
getLocaleData() => XuiLocaleDataReads the current locale pack (stable reference, rebuilt on locale change); also safe in SSR / DOM-less environments
registerLocale(locale: string, data: XuiLocaleInput) => voidRegisters or overrides a locale pack: shallow-merged per component group onto the existing pack of that locale, with uncovered groups falling back to the base; no notification when nothing actually changes
subscribeLocale(listener: (locale: string) => void) => () => voidSubscribes to locale changes (the callback receives the new locale name); returns an unsubscribe function
useLocaleData() => XuiLocaleDataComponent-level hook for both frameworks (Vue composable / React useSyncExternalStore); reads the locale pack inside components and reacts to switches

Contract Types ​

XuiLocaleData

ts
type XuiLocaleData = {
  modal: { ok: string; cancel: string };
  popconfirm: { confirm: string; cancel: string };
  table: { empty: string; selectAll: string; selectRow: (index: number) => string };
  pagination: { nav: string; prev: string; next: string };
  datePicker: {
    panel: string; prevMonth: string; nextMonth: string; placeholder: string;
    titleFormat: (year: number, month: number) => string; weekdays: string[];
  };
  skeleton: { loading: string };
  breadcrumb: { nav: string };
  select: { searchPlaceholder: string; searchAriaLabel: string; triggerPlaceholder: string };
};

The full locale pack structure (grouped by component; function fields ease translation across word orders).

XuiLocaleInput

ts
type XuiLocaleInput = Partial<XuiLocaleData>;

The input of registerLocale: provide only the groups to override; fields within a group are also partially overridden (shallow merge).

DEFAULT_LOCALE

ts
const DEFAULT_LOCALE = 'zh-CN';

The default locale constant; zh-CN and en-US packs are built in.

Notes ​

  • The default locale is zh-CN, with built-in messages identical to the historical hard-coded strings — zero behavior change on upgrade; en-US is built in as well, and both can be overridden via registerLocale.
  • Explicitly passed message props (e.g. Modal okText, Select placeholder) always take precedence over the locale pack; pack defaults apply only when a prop is not provided.
  • Locale state is purely in-memory (no DOM writes), so all APIs are safe under SSR; switching the locale immediately re-renders every mounted component without a refresh.
  • registerLocale merges shallowly per group: uncovered groups fall back to the base pack at registration time; overriding the current locale rebuilds the cache and notifies immediately, while overriding other locales applies silently until the next switch.
  • Switching the locale affects every component demo on this site; the locale persists after leaving this page and can be reset to Chinese with one click inside the demo.
